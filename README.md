# HistoryGuard

基于 **Chrome Manifest V3** 的本地历史记录自动过滤扩展，使用原生 JavaScript、HTML 与 CSS 构建，零第三方运行时依赖、不联网、不上传数据。

---

## 核心特性

- **实时自动清理**：启用总开关与对应规则后，访问匹配网址时自动从 Chrome 历史记录中移除，不在历史中保留记录。
- **新增即扫（可选）**：支持在添加或导入规则后立即扫描并清理已存在的匹配历史记录，也可按需关闭仅对后续访问生效。
- **三色状态图标**：
  - 🔵 **蓝色**：扩展正常运行，当前标签页未命中过滤规则
  - 🟢 **绿色**：当前标签页网址已命中启用中的过滤规则
  - ⚪ **灰色**：全局自动清理总开关已关闭
- **快捷添加与原地编辑**：一键识别当前标签页生成规则，支持 3 种快捷模板（主域名及子域名 / 精确主机 / 当前路径前缀），规则列表支持复选框启停与原地行内编辑（`Enter` 保存 / `Esc` 取消）。
- **可视化清理统计**：提供环形占比图与详细指标双页概览（带页面指示器切换），并按规则独立记录今日清理、累计清理与最近清理时间。
- **导入导出与批量管理**：支持一键全部启用、全部暂停、清空规则，以及 JSON 格式规则导出与去重导入。

## 安装方法

1. 打开 Chrome 浏览器，访问 `chrome://extensions/`。
2. 开启右上角的 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择本项目根目录（包含 `manifest.json` 的文件夹）。

## 规则语法与示例

### 常见示例

| 规则表达式 | 匹配说明 |
| --- | --- |
| `*://example.com/*` | 匹配 HTTP 与 HTTPS 下 `example.com` 的所有路径 |
| `*://*.example.com/*` | 匹配 `example.com` 主域名及其全部子域名（如 `sub.example.com`） |
| `https://example.com/private/*` | 仅匹配 HTTPS 协议下的 `/private/` 路径前缀 |
| `*://localhost:3000/*` | 匹配带显式端口号的本地服务 |
| `*://*/secret/*` | 匹配任意域名下的 `/secret/` 路径 |

### 匹配与规范化规则

- **协议**：仅支持 `http://`、`https://` 和 `*://`（同时匹配 HTTP 与 HTTPS）。
- **域名**：支持精确域名、`*.example.com` 与 `*`；其中 `*.example.com` 同时匹配主域名与子域名，不会误匹配相似域名（如 `badexample.com`）。
- **路径与查询参数**：仅 `*` 作为通配符，其余正则特殊字符按字面量匹配（不支持任意正则表达式）。
- **自动规范化**：新增与编辑时自动统一协议/域名大小写，去掉 `www.` 前缀在快捷主域名模式中的冗余部分，并自动阻止重复规则。
- **快捷添加限制**：`chrome://`、扩展页等非 HTTP(S) 页面会自动禁用快捷添加并提示原因。

## 统计口径与隐私

- **计数依据**：仅在 `chrome.history.deleteUrl` 成功返回后计入清理次数（包含新增/导入规则时的立即清理与后续访问的自动清理）；删除失败不计入次数并弹出提示。
- **归属规则**：多条规则同时命中同一访问时，仅执行一次删除，统计归属列表中**第一条启用且匹配**的规则。
- **统计隔离**：删除单条规则会移除该规则的明细统计，但保留全局累计统计；重置统计不会删除已配置的规则。跨日后“今日清理”自动归零。
- **本地隐私**：规则与计数全部存储在 `chrome.storage.local`，不记录被清理的 URL、网页标题或访问日志。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `history` | 扫描历史记录、监听 `chrome.history.onVisited` 并在命中规则时调用 `chrome.history.deleteUrl` |
| `storage` | 在 `chrome.storage.local` 中本地持久化保存规则、设置与统计计数 |
| `tabs` | 监听标签页切换与更新以动态更新扩展栏图标状态（蓝 / 绿 / 灰），并在打开弹窗时读取当前标签页用于快捷添加 |

> 不申请 `<all_urls>` 或网页内容脚本注入权限。详情见 [隐私政策](PRIVACY.md)。

## 项目结构

```text
historyGuard/
├── manifest.json         # Manifest V3 扩展配置
├── background.js         # 后台 Service Worker：历史监听、规则清理与图标同步
├── popup.html            # 弹窗页面结构（规则管理 / 清理统计 / 设置）

├── styles.css            # 弹窗样式与缓动动画
├── lib/
│   ├── rules.js          # 规则校验、规范化与通配符匹配引擎
│   └── state.js          # 状态持久化结构、统计归因与跨日重置

│   └── benchmark.js     # 零依赖规则匹配性能基准
├── icons/                # 蓝 / 绿 / 灰三套尺寸图标
└── tests/                # 单元测试与模拟 Chrome API 后台、弹窗测试
```

## 开发与测试

需要 Node.js 环境，运行规则、统计、模拟后台 API 和弹窗 DOM/Chrome mock 回归测试：

```bash
npm test
```

### 匹配性能基准

```bash
npm run benchmark
```

基准使用内存中的合成规则和 URL，不读取或删除浏览器历史。分别测试 10 / 100 / 1000 条规则下的未命中和命中最后一条规则场景；每组 500 个 URL，先预热 30 个 URL，再运行 3 次取中位耗时。

以下为同机 Node.js `v24.19.0` 的一次本地测量记录，单位为毫秒：

| 规则数 | 场景 | 优化前 | 优化后 |
| --- | --- | ---: | ---: |
| 10 | 未命中 | 12.29 | 1.20 |
| 10 | 命中最后一条 | 10.12 | 0.92 |
| 100 | 未命中 | 107.54 | 2.38 |
| 100 | 命中最后一条 | 104.95 | 2.18 |
| 1000 | 未命中 | 1177.91 | 64.57 |
| 1000 | 命中最后一条 | 1071.12 | 13.31 |

优化前数据来自实施前的只读基准；优化后复用已预热的规则编译缓存。耗时会随设备、JIT 和运行负载变化，不代表真实 Chrome 中的端到端性能，也不作为单元测试的时间阈值。

自动回归另验证：10 个独立匹配 URL 加重复记录仅调用 10 次删除，峰值 4 路并发且批次只保存一次；默认图标加 2 个标签页首次设置 3 次，重复同步不增加设置调用；弹窗首次打开及编辑/取消规则不重建隐藏统计页。

另在 Chrome `150.0.7871.187` 的独立临时配置中，通过扩展加载、原生弹窗与快捷添加识别、真实历史批量/实时删除及持久化、Enter/Esc 编辑、设置与统计重置、图标 API 去重的冒烟检查，未捕获异常为 0。无头检查不覆盖工具栏三色视觉或导入导出的系统文件对话框，这些仍需按下方清单手动验收。

## 手动验收清单

1. 在 `chrome://extensions/` 加载扩展，确认名称为 **HistoryGuard** 且图标显示正常、无控制台报错。
2. 访问一个测试网页使其进入历史记录，点击扩展图标，在“当前网页快捷添加”中选择模板后点击 **添加当前网站**，确认提示已清理匹配历史且 `chrome://history/` 中该记录已删除。
3. 切换到 `chrome://extensions/` 页面再打开弹窗，确认快捷添加输入框与按钮已禁用并显示不支持原因。
4. 在“规则管理”中测试复选框启停与 **编辑**（原地行内编辑、`Enter` 保存、`Esc` 取消）。
5. 切换到“清理统计”页，通过底部页面指示器在“环形图表”与“详细信息”间切换，确认卡片高度一致且明细统计准确。
6. 在“设置”页验证规则批量操作（全部启用 / 全部暂停 / 清空）及 JSON 导出与导入功能。
